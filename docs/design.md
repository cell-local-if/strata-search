# 设计说明

## 产品目标

文档检索需要在数据变化时保持结果正确，并逐步支持字段化文档、索引结构、复杂查询、持久化和稳定的查询视图。公开接口应让调用方明确区分文档键、正文、字段类型和查询行为。

## 当前结构

- `Document` 保存稳定的外部文档键和一段文本，构造时拒绝空白键；可附加类型化字段（文本、整数、布尔）。
- `SearchIndex` 按文档键存储 `Document`，提供插入、替换、查找、删除和查询。
- `Schema` 声明字段名、类型与是否必需；`insert_with_schema` 先完整校验再写入，未知字段、必需字段缺失、类型不匹配以不同的 `SchemaError` 变体返回，失败不改动索引。
- 查询按 Unicode 空白切分并转小写，扫描各文档寻找包含全部查询词项的结果。
- 数据仅在内存中存在，查询没有相关性评分或持久化承诺。

外部键是调用方提供的身份，不应依赖未来的存储位置、索引段编号或排序名次。正文原文与分析产生的词项应保持概念上的区分，避免后续加入分析规则时改写原始内容。

## 兼容原则

公开行为以 README 和测试中的契约为准。新增能力时需要明确旧调用的行为、错误边界与可观察结果。没有公开声明的能力不应由调用方假定存在。

结构化字段已实现：`Schema`/`FieldSchema` 声明字段，`FieldValue` 承载值，`insert_with_schema` 保证校验失败时旧文档与检索结果不受影响。字段过滤、查询语法扩展等能力在实现相应功能时确定。
